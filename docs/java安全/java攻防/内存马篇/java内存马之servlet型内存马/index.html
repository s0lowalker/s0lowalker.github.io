    Java 内存马之 Servlet 型内存马 #

    Servlet 创建 #

    创建一个 Servlet 的流程是init()->doXXX->destroy()。

    先看一下 Servlet 这个接口有哪些方法：

    public interface Servlet {  
   void init(ServletConfig var1) throws ServletException; // init方法，创建好实例后会被立即调用，仅调用一次。  
  
   ServletConfig getServletConfig();//返回一个ServletConfig对象，其中包含这个servlet初始化和启动参数  
  
   void service(ServletRequest var1, ServletResponse var2) throws ServletException, IOException;  //每次调用该servlet都会执行service方法，service方法中实现了我们具体想要对请求的处理。  
  
   String getServletInfo();//返回有关servlet的信息，如作者、版本和版权.  
  
   void destroy();//只会在当前servlet所在的web被卸载的时候执行一次，释放servlet占用的资源  
}

    从 Servlet 接口中我们可以看出，如果我们要写恶意代码，应该是写在service()中，所以这里我们直接创建一个恶意的 Servlet 类：

    package tomcatshell.servlet;

import javax.servlet.*;

            try {

            } catch (IOException e) {

            }
        }
    }

    @Override
    public String getServletInfo() {
        return "";
    }

    @Override
    public void destroy() {

    }
}

    我们在StandardContext#startInternal()中，进入fireLifecycleEvent()方法，之后又做了一次StandardWrapper的装载工作。

    跟进到loadOnStartup()方法；

    可以看到它对loadOnStartUp属性进行了判断：

    在 Servlet 的配置中，<load-on-startup>1</load-on-startup>的含义是：标记容器是否在启动时就加载这个 Servlet。当值大于等于 0 时，表示容器在应用启动时就加载这个 Servlet；当是负数或者没有指定时，则表示容器在该 Servlet 被选择时才被加载。正数的值越小，启动该 Servlet 的优先级越高。

    如果要在 web.xml 中配置应该是这样：<load-on-startup>1</load-on-startup>。

    这里对应的实际上是 Tomcat Servlet 的懒加载机制。

    很明显这里 web.xml 的内容不是我们可控的，所以必须要把恶意的 Servlet 放到最前面去加载。

    Servlet 内存马 #

    Servlet 工作流程总结 #

    首先获取到 HTTP 请求，然后读取到 web.xml，并且webConfig()方法中还创建了一个StandardWrapper，而我们的 Servlet 都会被保存到这个StandardWrapper中，后续这个 Wrapper 是放到 Context 中的，一个 Context 对应一个 Web 应用，可以包含多个 Wrapper，一个 Wrapper 对应一个 Servlet，负责管理 Servlet。在创建和加载完StandardWrapper之后，我们需要把加载的 Servlet 从StandardWrapper中读取出来，所以这里就到了我们最后的一个过程：加载 Servlet，对应有一个很重要的属性值——loadOnStartUp。

    Servlet 内存马的攻击 #

    攻击主要有几个关键点：

    1. StandardWrapper
    2. StandardContext
    3. 恶意 Servlet

    1. 获取StandardContext对象
    2. 编写恶意 Servlet
    3. 通过StandardContext.createWrapper()来创建StandardWrapper对象
    4. 设置StandardWrapper对象的loadOnStartup属性值
    5. 设置StandardWrapper对象的ServletName属性值
    6. 设置StandardWrapper对象的ServletClass属性值
    7. 将StandardWrapper对象添加进StandardContext对象的children属性中
    8. 通过StandardContext.addServletMappingDecoded()添加对应的路径映射

    Servlet 型内存马无法使所有请求都经过恶意代码，只有访问我们设定的 URL 才能触发，这是 Servlet 型内存马的缺点，而且容易被发现。需要先访问 Servlet.jsp，完成对内存马的注册，然后再访问/servletshell，并带上cmd参数才能实现命令执行。
